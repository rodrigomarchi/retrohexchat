# i18n

`config/i18n_locales.exs` is the **single source of truth** for the supported set.
Adding or dropping a language is a one-file edit: the Makefile list, the browser
catalog exports, and the Python checkers all derive from it via
`scripts/i18n/locales.py`. Never hardcode a locale list anywhere else.

Enabled: `en` + `pt_BR, pt_PT, es, fr, de, it, nl, pl, ru, id, ja, zh_hans, zh_hant`.
All are LTR — the RTL code path is retained but currently unexercised.

## Tooling (`scripts/i18n/`)

| Module | Responsibility |
|--------|----------------|
| `locales` | the supported set, parsed from the Elixir registry |
| `protection` | masking fragments a translator must not touch |
| `quality` | guards deciding whether output is fit to ship |
| `translator` | engines behind one interface, injectable in tests |
| `pipeline` | batching and fallbacks, pure of I/O and engine choice |
| `catalogs` | all catalog filesystem access |
| `glossary` | curated translations for the universal UI vocabulary |

Keep the modules pure and the engine injected — `ScriptedTranslator` is how the
tests drive the pipeline without Argos models. Add a regression test to
`scripts/tests/` for every translation defect you find in the wild.

## Rules

- **Never `dgettext` an identifier.** Audit-log action keys (`channel.create`),
  service names, and command syntax are literals. Translating them corrupts the
  audit log, which persists whatever string it is handed.
- **A bad translation is worse than English.** The pipeline rejects output that
  loses a placeholder, keeps a sentinel, loops, or collapses, and keeps the
  source instead so a human can see it needs work.
- **Never mask fragments with markup-shaped tokens.** Models treat them as tags
  and mangle them; sentinels are bare alphanumerics (`XPH0X`).
- **The curated-override pass matches a msgid, not a msgid in a domain, and its
  keys are unescaped text.** Two failure modes, both measured twice:
  `i18n_apply_translation_overrides.py` rewrites *every* catalog entry whose
  msgid appears in `PO_OVERRIDES`, so a short label you never touched (Kick,
  Auto, Status) is silently reset to whatever the script's curated value is —
  which may itself be stale against the glossary. Always scope it with the
  domain globs and **audit against a pre-run snapshot after each pass, not at
  the end**. And its parser unescapes before matching: a msgid containing a
  quote is keyed as `"` in the Python source, never `\"`. A key written with the
  PO file's escaping matches nothing at all, silently, and the entry ships empty
  in every locale — only `make i18n.catalog.check` says so.
- **Read every `#, fuzzy` guess before clearing the mark.** The msgstr under it
  was copied from a *different* msgid, and in practice it is always wrong:
  `%{count} reply` arrived as `%{count} user`, "Could not load more of this
  thread." arrived from the mentions list, "Opening a Thread" arrived as
  "Opening". See the memory `gettext-fuzzy-is-a-different-msgid`.
- **UI labels are a glossary, not a translation task.** One- and two-word labels
  have no sentence around them, so models pick the conversational sense: "OK"
  became "Está bem.", "No" became "Numéro", "Mute" became "Mignon". Add new
  button, menu and status labels to `scripts/i18n/glossary.py` rather than
  letting the pipeline guess. `OK` stays literal everywhere except Chinese
  (`确定`/`確定`), and no label ends in a full stop.

- **The order of the pipeline is not negotiable: extract → merge → machine →
  glossary → merge.** The engine happily overwrites a curated value — it turned
  "Timers" into "Relógios" on top of the glossary entry — and `make
  i18n.quality.check` reports that as *glossary drift*. Running the glossary
  before the machine translation leaves the drift in the catalog.
- **A run translates what is new, never what is merely untranslated.**
  `i18n_machine_translate_po.py` used to treat "this msgstr still reads as the
  English source" as pending work, so a pass meant for 96 new strings rewrote
  16.000 unrelated entries and every one had to be reverted by hand before the
  diff could be read. Empty and fuzzy entries are the new ones; English
  fallbacks are old debt that may be deliberate, and repairing them is now
  `--repair-fallbacks`, opt-in and run on its own. After any run, re-run
  `mix gettext.merge`: `polib.save()` re-wraps msgids in its own style and will
  fight the next merge.
- **`en` is filled by the same script**, with `--locales en`: the source locale
  takes an identity translator, so the msgid becomes its own msgstr. It used to
  be refused outright, which left the one step with no tool behind it.
- **Read the catalog diff before committing; no gate looks at the file's
  shape.** `polib.save()` rewraps every msgid it touches from one line to
  many, which gettext reads identically and `make ci` approves — and which
  then fights the next person's merge. One session left 75.000 lines of it.
  Normalise by re-running `mix gettext.merge` over **every** domain in both
  apps, not just the ones you edited: polib touched all of them. A correct
  diff comes out *smaller*, because the same pass drops duplicated `#:`
  reference lines that were already there.
- **Count empty entries with a parser, not `grep '^msgstr ""'`.** A wrapped
  msgstr opens with exactly that line and continues below it, so the grep reads
  every long translation as missing — and a script that "fixes" them on that
  basis deletes the continuation lines and the PO header with them.
- **Before inventing a label, look for one the product already has.** Five
  `aria-label` strings written for list names came back as "Outros nomes",
  "Anmeldungen" and "Pseudonimy"; each window's own translated title was both
  the truer name and five fewer strings to carry.

```bash
make i18n.quality.check   # collapse / degenerate / residue / glossary drift
make i18n.tooling.test    # the Python tooling suite
make i18n.glossary        # apply the curated UI label glossary
make i18n.repair          # re-translate unusable entries (needs the venv)
```

`make i18n.repair` and `make i18n.glossary` both read catalogs through `polib`,
so both need the throwaway venv — call the script with the venv's interpreter
rather than the target, which hardcodes `python3`. `make i18n.repair` also wants
`argostranslate` and `opencc-python-reimplemented`. Everything in `make ci` runs
on stdlib alone.

**Catalogs, routes and public URLs:** see
[`docs/AGENT-GUIDE.md` §16](../../docs/AGENT-GUIDE.md) for the localized URL model
(unprefixed English, BCP47 path segments, reciprocal hreflang, no catch-all
`/:locale`), and [`docs/reference/i18n-catalogs.md`](../../docs/reference/i18n-catalogs.md)
for the catalog conventions and locale roster.
